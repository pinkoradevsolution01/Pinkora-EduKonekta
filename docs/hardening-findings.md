# Security and quality hardening findings

| Severity | Area                     | Evidence                                                                             | Remediation                                                                                                                            | Status                                                                  |
| -------- | ------------------------ | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| High     | Dependency vulnerability | `npm audit --omit=dev` previously flagged Next.js 16.2.12 through PostCSS and Sharp. | Upgraded to Next.js 16.3.0-canary.107, which uses PostCSS 8.5.23 and Sharp ^0.35.3; the production audit reports zero vulnerabilities. | Remediated — monitor the canary until a stable equivalent is available. |
| Medium   | CSRF                     | Cookie-authenticated unsafe requests previously relied only on SameSite cookies.     | Reject unsafe requests with a supplied untrusted `Origin`; retain exact CORS origin and HttpOnly/SameSite session cookies.             | Remediated                                                              |
| Medium   | Browser protections      | API/web headers were not centrally enforced.                                         | Added anti-framing, MIME-sniffing, referrer, permissions, HSTS (production API), and web CSP headers.                                  | Remediated                                                              |
| Medium   | Sensitive logging        | Unhandled exceptions were logged as full objects.                                    | Log only the error class and opaque request ID; return a generic 500 response.                                                         | Remediated                                                              |
| Low      | Traceability             | Request IDs were client-selected without validation.                                 | Generate opaque IDs unless a constrained safe identifier is supplied; return it in headers and errors.                                 | Remediated                                                              |
| Low      | Restore assurance        | Restore exercise was undocumented.                                                   | Added quarterly isolated restore-test procedure and a 90-day review gate.                                                              | Remediated                                                              |

Authorization, tenant isolation, record-level relationship checks, input validation, rich-text sanitization, attachment metadata restrictions, rate limiting, audit trails, database indexes, responsive table-based dashboard views, and uptime health checks were reviewed. The automated authorization matrix and report-isolation tests pass. No critical or high authorization or application data-exposure defect was found in this pass.
